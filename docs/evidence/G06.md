### What was built
- `scripts/persistence/save_soak.gd`:
  - `--save-soak` rewrites one checkpoint (sequence number plus a 64 KiB payload) through `SaveService.write_record`, once per frame,
    continuing from whatever the last run left.
  - `--save-verify` prints which copy loads (current, temp or backup) and the state of each file.
- `boot.gd` runs these only with the `internal` feature or from the editor binary. The release export prints
  `save soak is not available in this build` and writes nothing (checked on the release export).
- `SaveService.inspect_files()` (diagnostics); internal builds flush the log on every print (`run/flush_stdout_on_print.internal`).
- `tools/save_kill_test.py`. Each cycle starts the exe headless, waits for `SOAK start`, sleeps 0-1.5 s at random, then kills it with
  `TerminateProcess` (what Task Manager "End task" and `taskkill /F` do). It then runs `--save-verify`. A cycle passes when a valid copy loads and
  its sequence number never goes backwards.

### What was run
```
py -3 tools/build_manifest.py --godot "$GODOT_BIN"
"$GODOT_BIN" --headless --path . --export-release "Windows Desktop (internal)" build/windows-internal/LightsBackOn.exe
```
