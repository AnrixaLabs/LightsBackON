## Observed result (tests/integration/test_V04_four_player_join.gd, 5 tests, all PASS)
- **Join during pump and repair**: P2 joins 4 s into the pump drain with 5 live ticks before its chunks finish; P3 joins between `remove` and
  `install` of the east repair; P4 after. All four mirrors end on the host's revision and canonical hash; every mirror shows R_JE_TRUNK restored;
  crew = [HOSTP, P2, P3, P4] (no duplicates); a fifth join is SESSION_FULL.
- **Revision barrier**: a joining peer's toggle is NOT_SYNCED with no state change; confirming an older revision is STALE_SNAPSHOT; then commands work.
- **Reconnect ghost**: P2 rejoins on a new connection while the old one is still registered: old lock released, one P2 in the crew, old peer UNKNOWN_PEER, hashes converge.
- **Content handshake**: content hash is 64 hex, deterministic, differs for different content; a mismatching hash is refused before spawning.
- **Chunks**: C01 snapshot needs several chunks; each encoded chunk message is at most `snapshot_chunk_bytes` (this test found that the first
  version bounded only the raw slice, which grew about 1.5x once escaped; fixed).
