- **Duplicate command changes switch once**: same bytes twice -> second reply `duplicate: true`, same revision, host revision and state hash unchanged; a different body under a used seq is also treated as the old command and not applied.
- **Invalid peer rejected**: unknown peer 99 and a removed peer -> UNKNOWN_PEER, state hash unchanged.
- **Invalid entity IDs rejected**: unknown switch, repair, panel, item and a malformed ID -> UNKNOWN_ENTITY / UNKNOWN_ITEM, state unchanged.
- Spawn: host player (peer 1) and two remote players admitted through the same path. Identity from transport (payload `player` ignored -> NOT_LOCK_OWNER; LOCKED_BY_OTHER names P1).
- Revision advances only on durable change (refusal and heartbeat do not). Envelope: wrong session, extra key, non-JSON, oversized, nested payload, seq 0 refused. Stale seq outside the 64 window refused while a recent one is a duplicate. Per-sender rate limit with sliding window. Host range check. NET08 logic (protocol/content mismatch rejected before spawn). Disconnect releases the lock. Deferred intents and Steam mode refused with clear codes.

Integration (tests/integration/test_F03_enet_dev_loopback.gd, PASS): real ENetMultiplayerPeer server and client in one process on 127.0.0.1;
the client sends the same toggle twice; the host reads the sender ID from `get_packet_peer()`; replies: first `ok`, second `duplicate` with the same
revision; the sign is enabled once. **Localhost ENet smoke test only; it is not a network result.**
