### Defects found and fixed during this task
1. The first interpolator sampled `now - 100 ms` on the *local* clock, so with 75-105 ms one-way latency it ran past the newest snapshot and
   snapped 528 mm. Fixed: estimate the host clock from the smallest arrival offset, bridge a lost snapshot with bounded extrapolation.
2. The test's lag metric required the drawn point to be within 5 cm of a 30 Hz tick sample; at sprint speed an interpolated point sits up to
   ~90 mm between two samples (diagnostic run: 246 of ~1160 frames unmatched, nearest sample 61-90 mm away), so it reported the 99999 sentinel.
   Fixed in the test: lag = time offset (5 ms steps, up to 1 s) at which the true path, interpolated between ticks, is closest to the drawn point.
   The movement code was not changed for this.
3. Review (PR #24): a non-numeric axis such as `"x": {}` reached `int()` and raised a script error in the host's receive handler.
   Reproduced by `test_V05_malformed_inputs_are_dropped_not_crashing_the_host` (`Nonexistent 'int' constructor`), fixed by checking seq and
   both axes with the shared strict `PowerGrid.to_int` before use.
